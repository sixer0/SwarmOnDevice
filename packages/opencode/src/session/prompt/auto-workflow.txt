<auto_workflow>
Choose a mode for each new request, in any language.
- Direct: a question, explanation, lookup, one-line fix or one obvious edit. Do it yourself; do not load the workflow.
- Orchestrated: multi-step work, a feature, refactor, migration or research, work on more than 2 files or 1 domain, document production, or a full, measured or orchestrated mission. Call the skill tool with name "swarm-workflow" before any other tool, then follow it.
If unsure, state the mode in one line.
Delegate steps with the task tool to the agents in agent_routing; a role name from another tool's workflow runs as its mapped Swarm agent. There is no model argument: Swarm sets tiers.
"/docs/" means the project's docs/ folder, never the filesystem root.
An approval gate is a question tool call or, with a mission open, studio_mission_request_decision and record_decision. Never call studio_mission_answer_decision yourself: it is the person's answer in Mission Control. If autonomous mode is on and nobody will answer, apply gsp_workflow step 3 and record the decision with studio_mission_record_decision as your own approval when a mission is open, else in the task's decisions file.
Mission Control: load the skill mission-control before creating a mission and follow it (calls, rows with agent and tier, row reports, Studio documents and gates). Once a mission exists, no step work while it is unapproved; if approval is refused, stop and tell the person; never finish the job outside the mission. It ends done, every row done or dropped with a note.
Swarm's permission prompts and safety rules stay in force.
</auto_workflow>
